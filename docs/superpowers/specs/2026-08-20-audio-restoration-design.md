## 1. 目的與範圍

修復**真人錄製的講課／直播人聲音軌**，處理五類問題：底噪、音量不一致、齒音、低頻隆隆、削峰。

### 明確不做的事（避免範圍蔓延）

- 不做剪輯、不刪口頭禪、不做配樂混音（屬 `media-use` 技能守備範圍）
- 不重新合成音色（AI 救援層例外，且僅限單一區段、需使用者明示同意）
- 不處理 TTS 合成音檔（`audio/` 底下那批 Fish Audio 產物不是本技能目標）

### 三層不一致問題

| 尺度 | 症狀 | 對應機制 |
|---|---|---|
| 秒級（句與句） | 離麥遠近、語氣輕重造成音量跳動 | 逐句純增益補償 + 增益平滑 |
| 分鐘級（錄音條件變化） | 換麥克風、換場地、不同時段拼接 | 噪音頻譜指紋分區，每區獨立降噪基準 |
| 檔案級 | ch01 與 ch05 錄音條件差異大 | 全部收斂到同一 LUFS 目標 |

## 2. 架構：兩階段 + 硬性人工閘門

```
analyze.py  ──►  report.json（診斷）+ plan.json（建議處理計畫）+ 人類可讀摘要
                        │
                   [ 使用者確認／手動調整 plan.json ]
                        │
restore.py  ──►  修復後檔案 + AB 試聽片段 + 前後指標對照
```

`restore.py` 缺少 `plan.json` 時直接報錯退出，不得自行推測參數。這是「先體檢、再提案、確認後才跑」的強制實現。

## 3. 語句切分：ASR 詞級時間軸為主

### 決策理由

不採用 `silencedetect` 單獨切句：它是音量門檻判斷，而本技能要處理的問題正是音量不一致。一句離麥過遠的話整句可能低於 −40dB 而被判為靜音、整句遺失。

不採用 SRT 字幕：SRT 時間戳為閱讀體驗調整過（合併短句、延長顯示時間），與實際發聲邊界誤差可達數百毫秒，用於增益切換會在人聲中間切換而產生可聽爆點。

採用 faster-whisper 的 `timeline.json`（詞級 `start`/`end`），因其為聲學模型判斷「是否有人在說話」，不受音量影響。本技能只需要時間軸，不要求文字正確性。

### 四種資料的分工

| 用途 | 來源 | 理由 |
|---|---|---|
| 語句邊界（增益切換點） | ASR `segments` + `words`，切換點置於詞間 gap 正中央 | 不受音量門檻影響 |
| 噪音採樣窗（降噪基準） | 詞間 gap > 0.6s **且** `silencedetect` 亦判定為靜音的區間 | 雙重確認；採樣窗混入人聲會導致降噪把人聲特徵消掉 |
| 非語音雜訊定位 | `silencedetect` 判定有聲、但 ASR 無任何詞的區間 | 咳嗽／翻頁／椅子聲須**壓低**而非拉平；誤判為語句會把咳嗽放大到人聲音量 |
| 分區切點（分鐘級） | 各噪音採樣窗的 FFT 頻譜指紋距離 | 建立於上述乾淨採樣窗之上 |

### timeline.json 取得策略

1. 音檔旁已有 `timeline.json` → 比對其 `info.duration` 與音檔實際時長，**誤差 ≤ 0.5 秒**才採用；超過視為不匹配（音檔被剪過），重跑 ASR。
2. 無 `timeline.json` → 自動跑一次 faster-whisper `small` 模型產生。
3. Python 環境三段 fallback：`.tmp/asr-venv` → 技能自帶 venv（`~/.audio-restoration/.venv`）→ 都無則引導使用者建立。`.tmp/` 為暫存目錄隨時可能被清除，不可寫死。

## 4. 體檢階段（analyze.py）

| 步驟 | 手段 | 產出 |
|---|---|---|
| 規格盤點 | `ffprobe` | 取樣率、聲道、時長、編碼、是否為影片 |
| 取得語句時間軸 | timeline.json（見 §3） | segments / words |
| 靜音交叉驗證 | `ffmpeg silencedetect` | 靜音區間清單 |
| 逐句／逐窗量測 | 單次全檔解碼（`ar/bulk.py`）+ numpy 切片 | 每句 RMS 與峰值、每個噪音窗 RMS（句級不量 LUFS——句級是相對補償，RMS 等價且免逐句 spawn ffmpeg） |
| 整檔量測 | `ebur128` 全檔單次（`measure_overall`） | integrated LUFS、true peak（寫入 report 頂層 `overall`） |
| 噪音指紋 | 噪音採樣窗 → numpy FFT | 每個採樣窗的頻譜特徵向量 |
| 分區偵測 | 相鄰指紋距離超過門檻 = 錄音條件變化點 | zone 邊界清單 |
| 逐區診斷 | 底噪 RMS、SNR、削峰樣本數、5–8kHz 齒音能量佔比、<80Hz 隆隆能量 | 每區問題清單與建議強度 |

分區偵測依據**底噪頻譜形狀**而非音量：換麥克風時音量可能不變，但噪音頻譜必變。

量測採**雙 buffer**（2026-08-21 效能改造）：原生取樣率 buffer 供 RMS／峰值（`afftdn` 的 `nf` 是絕對位準語意，16k 重採樣會截掉高頻噪音能量）；16kHz buffer 供指紋、診斷頻帶與殘響（`ZONE_THRESHOLD` 在 16k 下校準）。全部逐句／逐窗量測皆為 numpy 切片，analyze 全程的 ffmpeg 行程數為個位數（舊路徑約 2,800 次行程，1273 秒素材要跑 29.5 分鐘；改造後 36.2 秒）。

指紋距離定義：將每個採樣窗的 FFT 功率譜依 1/3 八度頻帶聚合並正規化為機率分布，取相鄰兩窗的餘弦距離。門檻初值 `0.15`，須在實作時以本專案實際素材校準；校準過程與最終值記入 `references/filter-cookbook.md`。

殘響指標定義：取語句結束時刻（ASR `words` 最後一詞的 `end`）之後 300ms 內的能量衰減斜率（dB/秒）。人聲在乾淨環境應急遽衰減；衰減緩慢代表空間殘響重。斜率門檻同樣需實測校準。

`plan.json` 中的 zone 邊界為建議值，使用者可手動增刪切點覆蓋自動判斷。

## 5. 修復階段（restore.py）處理順序

順序不可調換。降噪為門檻式運算，訊號位準決定何者被判為噪音；若各句位準相差 10dB，同一組門檻會削掉小聲句的氣音尾韻，對大聲句卻幾乎無作用。故必須先拉平。

1. **拉平（純增益，禁用壓縮器）**
   - 區級：每 zone 補償至共同工作位準 −20 LUFS
   - 句級：逐句補償，兩道保險：
     - 單句增益上限 `±6dB`（可調參數），避免將咳嗽、翻頁聲拉至人聲音量
     - 相鄰句增益差限幅 + 交界 200ms 線性斜坡，避免可聽的「呼吸感」
   - 使用純增益而非壓縮：壓縮會連帶頂高底噪，破壞後續降噪的訊噪比前提
2. **降噪** — 每 zone 使用自身噪音指紋，`afftdn` 強度依該區 SNR 選 12／18／24dB 三級
3. **低頻整理** — `highpass=f=60`，去冷氣聲、桌面震動、風切（男聲基頻約 85Hz 起，實作時取 60Hz 保留安全邊際，避免 2 階高通的 −3dB 點削掉低音域男聲，見 filter-cookbook）
4. **去齒音** — 僅在齒音能量佔比超標的 zone 掛 `deesser`，不無差別套用
5. **最終響度** — `loudnorm` 只用來**量測**，套用改純線性 `volume` 增益（實測發現：拉平後素材 LRA 過低時，loudnorm 的線性套用會靜默退回動態模式，把底噪連同人聲一起往上推），全檔統一且跨檔案共用同一目標
6. **限幅** — `alimiter` 收尾（處理目標 −2.0 dBTP，比驗收上限 −1.5 低 0.5dB 留 AAC 重編餘裕），確保 true peak 不超標

### 響度目標

寫成 `--target` 參數，預設 `-16`（Podcast／一般影音標準）。上架 YouTube 的版本可用 `--target -14` 重跑，避免被平台二次壓低。

## 6. 輸出

- **影片進** → `-c:v copy -c:a aac -b:a 192k` 換揉音軌，影像軌零重編、畫質無損
- **音檔進** → 同格式輸出
- 兩者皆額外產出 **16k mono WAV**，可直接餵給既有 `scripts/asr_to_srt.py`
- **AB 試聽片段**：自動挑選最吵的 30 秒，輸出修復前後對照
- **前後指標對照表**

批次模式：可對整個目錄執行，產出全部檔案的修復前後指標總表。

## 7. 驗證機制

修復完成後對輸出檔實測 after 指標（批次路徑：整檔一次解碼 + numpy 切片）；before 指標**直接讀 analyze 產出的 `report.json`（schema v2）**，不對原始檔重量測——兩端出自同一量測定義，配對比對才有意義。report.json 缺席或屬舊版時明確報錯要求重跑 analyze。四項硬指標（`ar/verify.py`）：

| 指標 | 合格條件 | 不合格代表 |
|---|---|---|
| 降噪淨效果 | 配對式淨壓制中位（每個噪音窗對其所屬句相減，消去共同增益）為負，且 **不超過 25dB**；before SNR ≥ 35dB 的乾淨素材回報「不適用」通過 | 為正 = 降噪未生效；壓制過大 = 降噪過頭，人聲被一併削除 |
| 響度收斂（Integrated LUFS） | 落在 `target ± 0.5` | 最終增益未收斂 |
| 真峰值（True peak） | ≤ −1.5 dBTP | 限幅失效 |
| 拉平生效（句間 RMS 標準差 `utterance_rms_stdev`） | 顯著小於修復前 | 拉平未生效（此為拉平成功的量化證據） |

任一項不合格即報告失敗並指出失效環節，不得靜默通過。

## 8. AI 救援層（方案 C）

觸發條件：某 zone 的 SNR < 10dB，或殘響指標超標。

行為：體檢報告標記該 zone 為「ffmpeg 濾鏡鏈無法救回」，詢問是否對**該區單獨**使用 DeepFilterNet。不為單一區段將整檔交給 AI 模型重新合成，因為 AI 修復會改變音色，講師的聲音會變得不像本人。

PyTorch 等依賴僅在使用者同意時才安裝，正常路徑不引入。
