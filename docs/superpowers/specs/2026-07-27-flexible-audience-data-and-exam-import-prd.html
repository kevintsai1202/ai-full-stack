彈性受眾資料與 Exam 測驗匯入

把「人物」與「每次問卷／測驗」拆開：人物依 Email 合併，但每次活動完整保留。Admin 統計依 Survey schema 自動呈現，並可篩選讀者後安全批次贈送點數或 VIP。

問題

目前 survey_response 同時放人物、同意狀態與固定問卷答案；匯入遇到既有 Email 就整筆略過，無法加入同一人的新測驗紀錄。

「不是重複的人就沒有新資料；同一個人可能填多份問卷、參加多場測驗。」

Goals

  • 新增 Survey 欄位不需 DB migration
  • 同一人保留多次問卷與測驗
  • 依答案、分數、來源與活動分眾
  • 所有資料可追溯來源與匯入批次

Non-goals

  • 不合併 Survey 與 Exam 資料庫
  • 不啟用 Exam 寄信功能
  • 不因參加測驗自動取得行銷同意
  • 第一版不做完整拖拉式表單設計器

User story：管理員

身為管理員，我希望按一下同步 Exam，先預覽新增、合併與錯誤筆數，再確認匯入，以便安全取得完整測驗名單。

User story：行銷

身為內容經營者，我希望篩出「參加特定測驗且低於 60 分」的人，以便寄送適合的補充教材。

User story：開發

身為開發者，我希望新增問卷題目只需更新 schema 與 mapping，不必修改 Entity、migration 與每個匯出器。

匯入規則

  • Email 已存在：合併人物，仍新增測驗 record
  • Exam attempt ID 已存在：依 payload hash 判定更新或 unchanged
  • 無 Email：列入錯誤，不建立行銷人物
  • 無 consent timestamp＋version：維持 pending

彈性 Survey 統計

圖表、篩選器、原始資料欄位與 PDF 共用 form schema。不同題型依欄位類型自動選擇呈現，不再把題目名稱寫死於 Admin HTML。

讀者篩選與批次贈送

可依訂閱、來源、VIP、點數、Survey、Exam 與最近活動篩選。批次操作先建立目標快照並預覽，再以 idempotency key 執行，避免重複發放。

排程寄送完成後移除操作 已完成

只有尚未到寄送時間的排程可以修改或取消。排程時間一到，寄送歷史必須移除「修改」與「取消排程」按鈕；後端 API 也要以伺服器時間再次檢查並拒絕逾時操作，避免舊頁面或直接呼叫 API 繞過限制。

  • 可操作條件：status = scheduled 且 scheduledAt > now
  • 到期後整理顯示狀態，不再持續顯示 scheduled
  • 逾時修改／取消回傳 409 Conflict
  • 未到期、已到期、跨時點競態與時區皆需測試

Rollout

Phase 0（已完成） — 修正寄送歷史排程生命週期；到期後移除修改／取消按鈕，API 同步拒絕逾時操作。
Phase 1 — 建立人物、同意、活動、Fact 與匯入稽核底座，回填現有 Survey。
Phase 2 — Admin 手動同步 Exam，匯入人物、填寫資料、結果與逐題答案。
Phase 3 — Survey schema 化，Admin 統計與匯出依 schema 自動呈現。
Phase 4 — 讀者動態篩選、選取快照與點數／VIP 批次操作。
Phase 5 — Campaign 動態分眾與 Exam cursor 排程同步。
