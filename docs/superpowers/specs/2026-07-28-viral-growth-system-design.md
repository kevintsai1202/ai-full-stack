# 電子報病毒成長系統設計

**日期**：2026-07-28
**狀態**：已完成
**範圍**：`survey-backend` 讀者端、管理後台、點數帳本與成長歸因

## 1. 摘要

- 把現有「確認訂閱後推薦人加點」擴充成雙邊獎勵、3／5／10 人里程碑與限時倍率活動。
- 建立分享點擊 → 填表 → 信箱確認的漏斗資料，後台可查看熱門文章與待審核邀請。
- 先用每日上限、速度偵測、資料庫冪等與人工審核守住點數帳務，再提高分享誘因。

## 2. 問題

> 「邀請里程碑、雙邊獎勵、分享漏斗、閱讀後提示分享、社群分享圖卡、限時加碼與防濫用。」

現有機制只記錄確認後的一筆推薦人獎勵，無法回答分享帶來多少點擊、填表與確認，也沒有活動倍率、被邀者獎勵、里程碑或異常審核。若直接放大獎勵，攻擊者可以用大量信箱或高速自動化累積點數，站方卻沒有暫停與審核手段。

## 3. 目標與非目標

### 目標

1. 每一位被邀者一生只歸因一次，重複確認與併發請求不重複發點。
2. 成功確認後，推薦人與被邀者都能取得可稽核的點數交易。
3. 3／5／10 人里程碑只頒發一次，徽章永久保留。
4. 後台看得到漏斗、熱門文章、活動與待人工審核項目。
5. 文章讀完才顯示低干擾分享提示，社群可取得適合連結預覽與限動的圖卡。
6. 每日上限與速度異常先進審核，未核准前不得先發點。

### 非目標

- 不承諾分享本身就發點；仍以被邀者完成信箱確認為獎勵條件。
- 不做現金、兌現或點數轉讓。
- 不用裝置指紋追蹤；點擊只使用隨機訪客代碼，後台不顯示 IP 或被邀者完整 email。
- 不追蹤 Facebook、Instagram 或 Threads 平台內部曝光數。

## 4. 成功指標

| 指標 | 定義 | 首期目標 |
|---|---|---:|
| 點擊→填表率 | 有推薦碼的填表數 ÷ 唯一分享點擊數 | 建立基線 |
| 填表→確認率 | 已確認歸因數 ÷ 有推薦碼填表數 | ≥ 55% |
| 分享採用率 | 看完文章後啟動分享操作的登入讀者 ÷ 完讀登入讀者 | ≥ 8% |
| 可疑邀請率 | 進人工審核數 ÷ 總確認歸因數 | < 5% |
| 重複發點 | 同一被邀者或里程碑的重複帳本交易 | 0 |

## 5. 使用者故事

- 身為讀者，我能看到下一個里程碑、已獲徽章與活動加碼，知道分享的回報。
- 身為被邀者，我完成信箱確認後可取得少量加碼點數；尚未建帳時，點數在首次登入安全補發。
- 身為文章讀者，我讀到文末才看到分享提示，不會在閱讀途中被彈窗打斷。
- 身為營運者，我能查看分享漏斗、熱門文章、活動成效及可疑邀請原因。
- 身為審核者，我能核准或拒絕待審項目；只有核准才發放雙邊、倍率與里程碑獎勵。

## 6. 資料與安全不變式

1. `referral_conversion.invitee_email_normalized` 唯一；一個 email 只能貢獻一次成功邀請。
2. `credit_txn` 仍只增不改不刪；餘額更新與帳本新增在同一交易。
3. 里程碑以 `(reader_id, milestone)` 唯一，帳本另以 `(reader_id, reason, note)` 唯一防重。
4. 限時活動只在確認時間位於活動期間且文章／hashtag 符合時套用；倍率上限 3。
5. 每日自動核准上限預設 10 人；10 分鐘內達 3 次確認開始累積風險，達門檻則轉人工審核。
6. 後台審核清單只回傳遮罩 email；公開端點不洩漏推薦碼是否存在、轉換是否成立。
7. 所有 migration 只能 additive；本次同時依前版規格補上 `survey_response.version` 樂觀鎖欄位。

## 7. 預設獎勵

| 項目 | 預設 |
|---|---:|
| 推薦人基本獎勵 | 100 點（沿用現況） |
| 被邀者確認加碼 | 20 點 |
| 3 人里程碑 | 開路者徽章 + 50 點 |
| 5 人里程碑 | 成長推手徽章 + 100 點 |
| 10 人里程碑 | 社群領航員徽章 + 300 點 |
| 每日自動核准上限 | 10 人 |
| 限時活動倍率上限 | 3 倍 |

讀者邀請頁以單一進度軸呈現 3／5／10 人節點，節點上方依序使用銅、銀、金獎盃；已達成節點高亮，並顯示距離下一階尚差人數。手機版改為垂直進度軸，避免節點標籤重疊。

## 8. 里程碑

### M1：帳務與風控

- 新增轉換、點擊、徽章、活動資料表。
- 確認事件建立轉換並計算風險；核准後才原子發點。
- 雙邊獎勵、里程碑、每日上限、速度偵測與人工核准／拒絕。

### M2：漏斗與營運

- 後台病毒成長頁：漏斗 KPI、熱門文章、待審核、活動建立與停用。
- 獎勵與上限加入既有參數設定。

### M3：讀者分享體驗

- 邀請頁顯示徽章、下一里程碑與進行中活動。
- 未登入訪客從專屬文章連結進站時，文章開頭與結尾都顯示可保留推薦碼、文章來源的免費訂閱入口；已登入者不顯示。
- 文章完讀提示「分享後賺點」。
- 動態產生 1200×630 社群預覽圖與 1080×1920 限動圖；加入 Open Graph。

## 9. 待上線後校準

- 每日上限應依真實確認分布調整，不用猜測值永久鎖死高成長讀者。
- 速度規則先採保守的可解釋門檻；累積樣本後再評估 IP 雜湊、網域集中度等訊號。
- 活動倍率是否提高「確認率」而非只提高點擊率，必須由漏斗資料判斷。
