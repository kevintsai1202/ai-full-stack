# 做一份電子報，其實是兩個獨立的問題

嗨，我是凱文大叔。

前兩期講了寄信要設哪些 DNS、以及那些設定會怎麼無聲失效。中間留了個尾巴：**如果你要從零做一份電子報，這封信到底要用什麼寄？**

今天把它講完。

常見有四條路，差別在於**你自己要扛多少**。

## 一、自建寄信伺服器

在自己的機器上跑 Postfix、Exim 這類 MTA。

成本最低（只有機器錢），控制權最完整。但你要自己扛的東西非常多：IP 信譽、PTR 反解、退信處理、被列進黑名單時的申訴、新 IP 的暖機期。

而且有兩個現實問題常常一開始就卡死人：**雲端業者的 IP 區段經常「出廠就在黑名單上」**，以及**很多供應商預設封鎖對外的 25 port**。

**建議**：除非你有資料落地或法遵上的硬需求，否則不要從這裡開始。送達率是靠時間養出來的，不是設定對就好。

## 二、寄信 API（交易信服務）

SendGrid、Resend、Amazon SES、Mailgun、Postmark、Zeabur ZSend 這類。你呼叫 API，它負責把信送出去。

IP 信譽、PTR、退信處理都變成服務商的事，你只要在 DNS 設好 SPF／DKIM／DMARC——也就是前兩期講的那些。

但要注意：**訂閱表單、名單管理、退訂連結、開信統計，全部都要自己寫。**

**適合**：已經有自己的系統，想把寄信整合進去。

## 三、電子報 SaaS 平台

Substack、beehiiv、Kit（原 ConvertKit）、Mailchimp、MailerLite 這類，開箱即用。

訂閱表單、名單、退訂、模板編輯器、開信率、甚至付費訂閱金流，全都內建。DNS 通常只要照它給的紀錄貼上去就好。

代價是：資料在別人手上、版面受限、名單規模大了之後費用相當可觀、想做客製化功能通常沒得談。

**適合**：內容是主角，不想碰技術。

## 四、自架開源電子報系統

Listmonk、Ghost、Mautic 這類，你自己部署那套軟體。

名單和資料完全在自己手上，功能又比從零自己寫完整得多。但有個關鍵細節：**它底下通常還是接一個寄信 API 或 SMTP relay**。

換句話說，這是「第三種」的介面，配上「第二種」的出口。

而這正好帶出今天真正想講的事。

## 關鍵：這其實是兩個問題，不是一條光譜

上面四種很容易被排成一條「從最麻煩到最省事」的直線。但它們其實是**兩個獨立的問題疊起來**的：

| | 名單／內容／統計歸誰管 | 實際把信送出去的是誰 |
|---|---|---|
| 自建伺服器 | 自己寫 | 自己的 MTA |
| 寄信 API | 自己寫 | 服務商 |
| SaaS 平台 | 平台 | 平台 |
| 自架開源 | 開源軟體 | 通常仍是服務商 |

看出來了嗎？「自架開源」根本不在那條直線上——它在名單這格是自己掌握，在送信那格卻是外包。

**把這兩格分開想，選型就清楚了**：

- 你想**擁有自己的名單**，不代表你得自己養 IP 信譽
- 你**不想碰 DNS**，也不代表你只能用 SaaS

多數人卡住，是因為把「我想掌握資料」直接翻譯成「那我要自己架伺服器」。這兩件事其實可以分開決定。

## 順帶一提：這也決定了你要扛多少 DNS 工作

接續上一期的主題：

| 方式 | 你要設的 DNS |
|---|---|
| 自建伺服器 | SPF／DKIM／DMARC／PTR／IP 信譽**全都是你的事** |
| 寄信 API | SPF／DKIM／DMARC 要設，PTR 歸服務商 |
| 自架開源 | 同上（因為出口還是服務商） |
| SaaS 平台 | 多半照著它給的紀錄貼上就好 |

## 那我自己選了哪一種？

你現在看到的這封，是**第二種再往前一步**——名單、訂閱、退訂、付費牆、寄送統計全部自己寫，寄送出口走 API。

用上面那張表來說，就是「名單自己管、送信外包」。

會這樣做不是因為它最好，而是因為我想把整套流程當成課程的實作案例。它牽涉到資料庫設計、HMAC 退訂驗證、寄送額度控管、權限判定——麻雀雖小，但該有的企業級系統零件都在裡面。

代價是很多細節得自己踩。上一期提到「SPF 被新增的服務覆蓋掉」那個坑，就是我自己踩的。

## 所以你該選哪一種？

給三個實際一點的判斷句：

- **只想好好寫內容，不想碰技術** → SaaS 平台。不要為了「掌握資料」去扛你不想扛的東西。
- **已經有自己的產品和使用者資料，想把電子報整合進去** → 寄信 API。
- **想擁有名單、也願意維護一套系統，但不想養 IP** → 自架開源 + 寄信 API。

至於自建 MTA——除非你有法遵或資料落地的硬需求，否則我會建議先跳過。它省下來的錢，通常買不回你花在黑名單申訴上的時間。
