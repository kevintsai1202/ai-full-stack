## 內文（Markdown）

```markdown
## 嗨，我是凱文大叔，這是第一封信

先謝謝你按下訂閱。這封信沒有教學、沒有優惠，只想說明我為什麼決定開始寫電子報。

我最主要的流量一直在 YouTube。但拍一支影片的時間比想像中長很多：查資料、寫腳本、錄、剪、上字幕，一輪下來好幾天。問題是 AI 這個領域跑得太快了——新模型發表、好用的工具冒出來、限時免費或折扣的資訊，這些東西的保鮮期常常只有幾天。等我影片剪完上架，消息已經過時了，甚至優惠都結束了。

我也試過先發 Facebook 和 Threads 救急。但只要貼文裡有連結，觸及就掉得很明顯，該看到的人反而看不到。平台不希望你把人帶走，這我理解，只是對「我想趕快讓你知道這件事」來說很不好用。

所以趁這次新的線上課上架，我順手把電子報的功能也做起來了。往後只要有新的心得、新的技術、值得抓的優惠，我可以第一時間直接寄到你的信箱，不用等影片、也不用跟演算法拔河。

接下來我會再單獨做一個電子報入口網站，讓訂閱、翻舊期、分享給朋友都更順一點，也希望內容能傳得更遠。

初期完全不收費，所以我打算把乾貨都放進來。這封信之後，你會陸續收到：

- **實戰踩雷筆記**：RAG、AI Agent、全端整合做下去真正卡住的地方，以及怎麼解
- **新模型與新工具的第一手觀察**：不是複述官方公告，是我實際跑過之後覺得值不值得學
- **優惠與免費資源**：AI 產品的活動，以及我自己線上、線下課程的專屬優惠

## 順便聊聊：這封信是怎麼寄出來的

既然是技術電子報，第一封信就從自己的實作講起。

以前要做電子報，你得先有一個「真的信箱」，再接一套 email 行銷平台，處理退訂、寄送紀錄、額度這些雜事。現在不用了。像 [Resend](https://resend.com/) 或 Zeabur 提供的 [ZSend](https://zeabur.com/) 這類寄信服務，不需要傳統信箱、也不需要專門的 email 行銷服務，只要打一支 API 就能把信寄出去。

大概是這樣的一支請求：

    POST https://api.example.com/v1/emails
    Authorization: Bearer <你的 API Key>

    {
      "from": "凱文大叔 <noreply@你的網域>",
      "to": "reader@example.com",
      "subject": "為什麼我開始寫電子報",
      "html": "<p>信件內容</p>"
    }

對開發者來說，這件事的意義是：**寄信從「要串接的服務」變成「一個函式呼叫」**。剩下的力氣就能花在真正重要的地方——名單怎麼合法取得、退訂連結怎麼防偽、每日額度用完了要怎麼分天寄、哪些信真的被打開了。

我這套系統目前就是這樣長的：

- 訂閱走**二次確認（double opt-in）**，你按過確認我才會寄信，沒確認的一封都不寄
- 每封信頁腳的退訂連結都是**你專屬**的簽章連結，別人偽造不了，按一下就生效
- 內文用 Markdown 寫，寄出前自動轉成排版好的 HTML，我不必手刻信件版面
- 寄送額度會即時偵測，一批寄不完就分天續寄，不會重複騷擾同一個人

這些細節我後面會拆開來，一篇一篇講清楚，包含程式碼。

如果你手上也有想寄的名單，或正在猶豫要不要自己做一套，歡迎直接回信告訴我你卡在哪。你的問題大概就是下一期的題目。

下次見。

—— 凱文大叔
```
