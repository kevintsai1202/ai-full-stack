```markdown
# 你的信進垃圾桶，可能不是程式的問題

嗨，我是凱文大叔。

你把寄信功能做完了。註冊信、通知信、電子報，程式跑得好好的，API 回 200，log 顯示 `sent`。

然後你收到一則訊息：

> 「我沒收到信耶。」

去垃圾郵件匣一看，信在那裡。

這時候很多人會回頭檢查程式碼——但問題通常不在那裡。因為**收件伺服器根本不認識你的程式**，它只認得你的網域，以及你在 DNS 上留下的那幾行字。

那幾行字，決定了 Gmail 要不要相信「這封聲稱來自你的信，真的是你寄的」。

今天先把觀念講清楚：**那幾行字各自在回答什麼問題。**

## 收件伺服器在問三個問題

一封信送到 Gmail 門口，它不會直接放行，而是會問：

1. **這封信真的是從那個網域授權的伺服器寄出的嗎？** → SPF 在回答
2. **這封信在路上有沒有被改過？** → DKIM 在回答
3. **前兩題沒過的話，我該怎麼處理？** → DMARC 在回答

這三個不是三選一。2024 年起，Gmail 和 Yahoo 對大量寄件者的要求就是三個全都要有。

## 先澄清一個最常見的誤會：MX 跟寄信無關

還有一個角色叫 **MX**，但它回答的是完全不同的問題：**別人要寄信給這個網域，該送到哪台伺服器？**

**MX 管的是「收信」。** 你能不能把信寄出去、寄出去會不會進垃圾桶，跟 MX 一點關係都沒有。

所以「我 MX 設好了，為什麼信還是進垃圾桶」——因為收件方在判斷要不要信任你的時候，根本不會去查你的 MX。

反過來也成立：你可以只寄不收（`noreply@` 就是這樣，網域上根本沒有 MX），也可以只收不寄（把 MX 指向轉寄服務，這種情況**不需要動 SPF**）。

搞清楚這件事，你才不會在「只是想加個聯絡信箱」的時候，去亂改 SPF 而把原本正常的寄信搞壞。

## SPF：誰可以用我的網域寄信

SPF 是一份**白名單**。你在 DNS 上公告：「只有這些伺服器，可以用我的網域寄信。」

```
類型：TXT
名稱：@
內容：v=spf1 include:_spf.google.com include:sendgrid.net ~all
```

`include:` 的意思是「這家服務商名單上的伺服器，也算我授權的」。所以你每多用一家寄信服務，就多一個 `include`。

收件伺服器收到信，看一下是從哪個 IP 來的，再查你的 SPF，比對「這個 IP 在名單上嗎」。

## DKIM：信件的防偽封條

DKIM 用的是非對稱加密。寄信時用**私鑰**對信件簽章，收件方從你的 DNS 取得**公鑰**來驗證。

```
類型：TXT
名稱：selector._domainkey
內容：v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOC...
```

驗過了代表兩件事：這封信確實是握有私鑰的人寄的，而且**內容沒有被竄改**。

**DKIM 有一個 SPF 沒有的優勢：它撐得過轉寄。**

SPF 一被轉寄就失效，因為轉寄之後寄件 IP 換成轉寄伺服器的，一定不在你的白名單上。這是先天限制，不是設定錯誤。而 DKIM 的簽章跟著信件走，轉寄幾次都還在。

這也是為什麼你**兩個都要設**——它們涵蓋的情境不一樣。

## DMARC：沒過的時候怎麼辦

SPF 和 DKIM 各自回答了「這封信可不可信」，但它們沒有回答**「不可信的時候該怎麼辦」**。

以前這是收件方自己猜的。DMARC 讓你可以明確宣告：

```
類型：TXT
名稱：_dmarc
內容：v=DMARC1; p=none; rua=mailto:dmarc@example.com
```

`p=` 就是那個處置政策，有三種：**只觀察**（`none`）、**丟垃圾桶**（`quarantine`）、**直接拒收**（`reject`）。

還有一個常被低估的功能：`rua=` 會讓收件方**定期把統計報告寄給你**——有哪些來源在用你的網域寄信、其中哪些沒通過驗證。很多人是在這裡才發現自己完全忘記的系統。

## 順帶一提：寄信這件事，有四種做法

前面講的都是「信要能寄到」。但如果你是從零開始，其實還有個更前面的問題：**這封信要用什麼寄？**

常見有四條路，差別在於你自己要扛多少：

1. **自建寄信伺服器**（Postfix、Exim）——控制權最完整，但 IP 信譽、退信、黑名單申訴全是你的事
2. **寄信 API**（SendGrid、Resend、Amazon SES、Postmark、Zeabur ZSend）——送信交給服務商，但名單、訂閱、退訂要自己寫
3. **電子報 SaaS 平台**（Substack、beehiiv、Kit、Mailchimp）——開箱即用，代價是資料在別人手上
4. **自架開源系統**（Listmonk、Ghost、Mautic）——名單自己掌握，但底下通常還是接一個寄信 API

這題我會單獨開一期講，尤其是一個很多人會搞混的地方：「誰管名單」跟「誰把信送出去」其實是兩個獨立的問題。

（先說我自己：你現在看到的這封是第二種——名單、訂閱、退訂、付費牆全部自己寫，寄送出口走 API。）
```
