# IssueFlow MVP 共用案例需求：任務依賴與下一步建議

> 本文件是 [IssueFlow 專案作業](issueflow-project-assignment.md) 的功能需求底稿。產品語言可以稱 Issue，現有 lab 程式仍可沿用 Task 命名。

## 背景

我們有一個簡單的 IssueFlow 任務工作台。使用者可以看到單一專案中的 Issue、優先級與完成狀態，但目前看不出 Issue 之間的先後關係。這次只做一個最小功能：讓前置任務完成狀態影響後續 Issue 的可執行性。

## 必要行為

1. 任務可以指定一個前置任務。
2. 前置任務未完成時，後續任務顯示 `BLOCKED`。
3. `BLOCKED` 任務不能被標記完成。
4. `BLOCKED` 任務不應被推薦為下一步。
5. 前置任務完成後，後續任務解除 `BLOCKED`。
6. 頁面可顯示目前完成比例與下一個可執行任務。
7. 同優先級時，建立時間較早者優先；若時間相同，id 較小者優先。

## 刻意保留的未知數

- `BLOCKED` 是儲存在資料中的狀態，還是由 `dependsOnTaskId` 與前置任務狀態推導？
- 前置任務被刪除時，後續任務要解除阻塞、禁止刪除，還是顯示資料錯誤？
- 前置任務完成後，畫面要即時更新，還是下一次查詢時更新即可？
- 任務是否允許多重前置任務？本課第一階段先假設最多一個。

## 第一階段不做

- 登入、角色與權限。
- 多人即時同步。
- 正式資料庫與 migration。
- 多重前置任務、循環依賴與批次編輯。
- 產品級效能與無障礙完整稽核。

## 最小資料

```json
[
  {
    "id": 1,
    "title": "定義任務資料",
    "priority": 1,
    "createdAt": "2026-08-09T09:00:00+08:00",
    "status": "TODO",
    "dependsOnTaskId": null
  },
  {
    "id": 2,
    "title": "建立阻塞狀態呈現",
    "priority": 1,
    "createdAt": "2026-08-09T09:01:00+08:00",
    "status": "TODO",
    "dependsOnTaskId": 1
  }
]
```

## 最小驗收案例

| 案例 | 初始狀態 | 操作 | 預期結果 |
|---|---|---|---|
| A | 任務 1 未完成、任務 2 依賴任務 1 | 開啟頁面 | 任務 2 顯示 `BLOCKED`，不可完成 |
| B | 同上 | 完成任務 1 | 任務 2 解除 `BLOCKED`，進度增加 |
| C | 同上 | 嘗試直接完成任務 2 | 操作被拒絕，狀態不變 |
| D | 多個可執行任務同優先級 | 取得下一步建議 | 依建立時間，再依 id 排序 |
| E | 依賴 id 不存在 | 載入資料 | 顯示可追蹤錯誤，不得靜默當作無依賴 |
