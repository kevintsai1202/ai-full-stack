# 開場｜課程總覽、共用情境與這門課怎麼上

> 本篇是整門課的開場，在環境安裝之前先說明課程路線與共用情境，再介紹影片與網站的使用方式；**不列入 Hahow 官方 36 單元**。

## 單元定位

本節要解決的問題：讓學員在開始環境安裝前，先知道這門課要走哪條路、最後要交付什麼，以及所有操作共同使用的 AI CRM 情境；接著再說明影片與教學網站的使用方式。學員最常見的挫折不是聽不懂，而是「不知道現在為什麼要做這件事」、「當下懂了、回家忘了指令」或「跟不上示範的節奏」。這一節要先建立全課地圖與共同語境，再提前拆掉後兩個焦慮。

與前後節的銜接：本節先承接 teaching-site 的「課程總覽」與「貫穿全程的 AI CRM 情境」，再說明影片／網站分工；接下來的章節 1 單元 1 才會開始實際把開發環境裝起來。

建議時長：8～10 分鐘。

## 教學素材

### 先看課程總覽與共用情境

這段內容直接對齊 `teaching-site/course-data.js` 的 `meta`、`overview` 與 `sharedCase`。在請學員開啟終端機以前，先回答三個問題：我們要完成什麼、會怎麼一路完成、後面的資料與 AI 回答是在服務誰。

#### 這門課最後要完成什麼

- **課程規模**：32 小時，分成四天的混成學習路線。
- **核心產出**：一套「AI CRM 智慧業務助理」，從登入、客戶管理、商機與互動紀錄，到 AI 對話、SSE 串流、RAG 知識庫與 agent trace。
- **技術路線**：前半段先建立 Spring Boot、REST、JPA、Flyway、Security 與 React 工作台；後半段再把 Spring AI、tool calling、RAG 與 MCP 接回同一個 CRM domain。
- **完成標準**：本機自動化驗收通過、結訓測驗完成，並在 Demo Day 展示從登入到 AI 對話的完整流程。

#### 貫穿全程的三家 B2B 客戶

後面建立的 `Customer`、`Opportunity`、`Interaction` 與 `Task`，都不是抽象練習資料，而是服務以下三種業務狀態：

| 客戶 | 情境 | 課程中要回答的業務問題 |
|---|---|---|
| 亞太智能製造（APIM） | 高價值活躍客戶，近期有生產線 AI 預測維護商機 | 如何掌握活躍客戶的商機與下一步行動？ |
| 環球零售巨擘（GlobalMart） | 流失風險客戶，合約將到期且有未解決的效能客訴 | 如何從互動紀錄判斷風險並提出挽回建議？ |
| 鼎峰金融科技（ApexFin） | 續約延遲客戶，合約已過期且商機停滯 | 如何找出停滯原因，讓業務做出有資料支撐的決策？ |

因此，先講情境不是額外的故事，而是讓學員知道後續每個 API、畫面與 AI 回答的驗收基準。之後看到一個數字，要能回到真實 CRM 資料；需要摘要、風險或行動建議時，才交給 AI 撰寫。全課共同遵守：「數字由程式算、文字由 AI 寫」。

### 兩個載體，兩種責任

這門課由兩個部分組成，各自負責不同的事：

- **影片**：負責「帶你走一遍」。示範操作、講解為什麼這樣做、示範遇到錯誤時怎麼判斷。
- **教學網站**：負責「讓你查得到」。所有提示詞、指令、下載連結、參考文件都在上面，隨時可以複製貼上。

教學網站網址：<https://kevintsai1202.github.io/ai-full-stack/>

這樣分工的理由很單純：影片適合傳達脈絡與判斷，但不適合當工具書——沒有人想為了找一行指令而把影片拉來拉去。所以課堂上該做的事只有一件：**理解為什麼**。至於指令怎麼拼、網址是什麼，全部交給網站。

### 影片可以重複觀看

課程影片可以無限次重複觀看，沒有觀看期限限制。實務上建議這樣用：

- **第一遍**：不要跟著操作，先純粹看完，理解這一節在解決什麼問題。
- **第二遍**：開著網站跟著做，卡住就暫停。
- **之後**：只在需要時回頭看特定段落，其他時候直接查網站。

課堂上跟丟是正常的，因為示範的節奏一定比你自己動手快。跟丟時不必焦慮，繼續看完該節，之後再回放。

### 教學網站上有什麼

每個單元在網站上都有對應的頁面，包含：

- **學習目標與核心概念**：這一節要達成什麼、有哪些關鍵觀念
- **示範提示詞**：課堂上示範用的完整提示詞，**Windows 與 macOS 各有一份**，可直接複製
- **分類提示詞**：依用途分成建置（build）、驗證（verify）、排錯（fix）等類別，遇到不同狀況取用不同的提示詞
- **實作任務清單**：這一節做完應該完成哪些事，可以逐項核對
- **參考圖解**：架構圖與流程圖

除了單元頁面，網站上還有：

- **下載教材**：7 份主題文件（開發環境安裝指引、REST API 命名規範、Docker PostgreSQL 與 pgvector 設定、pgvector 向量檢索指令、JWT 架構與認證流程、React 與 Axios 整合、Spring AI 與 Tool Calling 架構）
  - 網站上另有一份 Embabel 黑板機制與 GOAP，資料裡標注為「選修附錄」、非正式單元，開場不提
- **隨堂測驗**：檢查自己是否真的理解
- **附錄**：術語表、常見問題、驗收檢核清單

### 不需要抄的三樣東西

課堂上請不要花時間抄以下內容，它們都在網站上：

1. **安裝指令與下載網址**——所有工具的官方下載連結都列在網站與教材裡
2. **示範用的提示詞**——完整原文都可以複製，包含 Mac 版本
3. **驗證命令與預期輸出**——每一節該執行什麼、看到什麼才算過關，網站都寫明了

把手空出來，專心聽「為什麼」。

## 口語稿

嗨，歡迎來到「駕馭 AI 的全端實戰養成班」。在我們開始裝任何東西、寫任何一行程式之前，我想先花五分鐘，跟你講一件很重要、但很多課程都不會講的事：這門課，你該怎麼上。

不過在講影片怎麼看之前，我們先把整門課的地圖跟共同情境看懂。這門課總共三十二個小時，會用四天的節奏，從 Spring Boot、REST、JPA、Flyway、安全認證與 React 工作台開始，接著把 Spring AI、SSE、tool calling、RAG 與 MCP 接回同一個 CRM 專案。最後交付的不是零散的練習，而是一套可以登入、管理客戶、讀取真實資料、進行 AI 對話，還能追蹤 agent 決策的 AI CRM 智慧業務助理。完成標準也很清楚：本機驗收要通過，結訓測驗要完成，最後在 Demo Day 把完整流程跑給大家看。

接著先認識這套 CRM 服務的三家客戶。亞太智能製造是高價值、互動活躍的客戶，最近有一筆生產線 AI 預測維護商機；環球零售巨擘是流失風險客戶，合約快到期，還有一筆效能客訴沒有解決；鼎峰金融科技則是續約延遲客戶，合約已經過期，商機也停滯了。後面我們建立的 Customer、Opportunity、Interaction、Task，以及 AI 助理讀到的資料，都會回到這三種業務狀態。這樣你就不會只是在背 API，而是知道每個功能到底要幫哪一種客戶做決策。

所以，接下來看到一個數字，要記得由程式從 CRM 資料算出來；需要摘要、風險或下一步建議時，才讓 AI 寫成業務人員看得懂的文字。這就是整門課的共同驗收邊界：「數字由程式算、文字由 AI 寫」。有了這張地圖，我們再來說明影片跟教學網站各自負責什麼。

先說一個我看過太多次的狀況。學員在課堂上聽得很專心，也跟著做了，回家之後想自己再跑一次，卡住了——不是不會，是想不起來那行指令怎麼打。然後他開始拉影片，一分鐘一分鐘往前找，找了十分鐘，熱情就這樣被磨掉了。另一種狀況是反過來的：他怕忘記，所以整堂課都在抄筆記，抄得很認真，但我在台上講的「為什麼要這樣設計」，他一句都沒聽進去。

這兩種狀況，我都不希望發生在你身上。所以這門課刻意設計成兩個部分，各自負責不同的事。

第一個部分是影片，也就是你現在正在看的。影片負責帶你走一遍：我會實際操作給你看，會告訴你為什麼要這樣做，也會故意示範遇到錯誤的時候怎麼判斷——因為排錯的思路，是文字最難傳達、但影片最擅長的東西。

第二個部分是教學網站。網址等一下會放在畫面上，你也可以在課程資訊裡找到。網站負責的事情只有一個：讓你查得到。所有的提示詞、所有的指令、所有的下載連結、所有的參考文件，全部都在上面，而且可以直接複製貼上。

為什麼要這樣分？因為影片適合傳達脈絡跟判斷，但它非常不適合當工具書。沒有人想為了找一行指令，把影片拉來拉去。所以我要跟你講這門課最重要的一句話：**課堂上你只需要做一件事，就是理解為什麼。至於指令怎麼拼、網址是什麼，全部交給網站。**

具體來說，有三樣東西請你不要抄。第一，安裝指令跟下載網址——所有工具的官方連結都在網站跟教材裡，一個都不缺。第二，我示範用的提示詞——完整原文都可以複製，而且我準備了 Windows 跟 macOS 兩個版本，你用哪一台都不會卡住。第三，驗證命令跟它應該長什麼樣——每一節做完該執行什麼、看到什麼才算過關，網站上都寫得清清楚楚。這三樣你都不用抄，把手空出來，專心聽。

我們來看一下網站上實際有什麼。每一個單元都有自己的頁面，裡面有這一節的學習目標跟核心概念，有示範提示詞，還有依用途分類的提示詞——建置一組、驗證一組、排錯一組，你遇到什麼狀況就用哪一組。再往下有實作任務清單，你可以一項一項核對，確認這一節該做的都做了。除了單元頁面之外，還有七份下載教材，涵蓋開發環境安裝、REST API 命名規範、Docker 跟 pgvector 設定、pgvector 的向量檢索指令、JWT 認證流程、React 前後端整合，還有 Spring AI 的 Tool Calling。另外也有隨堂測驗，跟包含術語表、常見問題、驗收清單的附錄。

還有一件事我要特別強調：這些影片你可以無限次重複觀看，沒有期限。我建議你這樣用——第一遍不要跟著操作，就純粹看完，理解這一節到底在解決什麼問題；第二遍再開著網站跟著做，卡住就暫停；之後你大概只會為了特定段落回來看，其他時候直接查網站就夠了。

所以，如果你在課堂上跟丟了，完全不用焦慮。我示範的節奏一定比你自己動手快，這是正常的。跟丟的時候，不要慌著暫停倒帶，先把這一節看完，理解我在幹嘛，之後再回來慢慢做。你有無限次的機會。

好，這門課怎麼上，就是這樣：影片帶你走一遍，網站讓你查一輩子。接下來我們進入章節一的第一節，開始把開發環境準備起來——而你會發現，連安裝這件事，我們都不打算自己一個一個做。我們下一節見。
