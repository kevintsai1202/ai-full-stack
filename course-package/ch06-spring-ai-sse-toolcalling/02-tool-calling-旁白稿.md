# 02-tool-calling｜工具呼叫旁白稿

本稿依據 `02-tool-calling.md` 的教學素材與口語稿整理，供人工錄音使用。共 8 段，錄音時可依段落分開保存，方便後續與投影片時間軸對齊。

建議錄音格式：WAV 或 MP3。每段開頭保持自然，結尾保留約 0.5 秒空白。

## 01｜上一節留的坑

建議檔名：`01-the-gap.wav`

上一節結束的時候我留了一個坑：我們的 AI 助理會聊天、有記憶，但你問它「亞太智能製造的生意機會金額多少」，它會很有自信地給你一個數字——一個編出來的數字。

為什麼模型會編？因為大語言模型的知識來自訓練語料，你資料庫裡的客戶資料它從來沒看過，但它的天性是「一定要給你一個答案」。企業系統最怕的，就是這種一本正經的胡說八道。這一節，我們就來把這個洞補起來。

## 02｜Tool Calling 的本質

建議檔名：`02-tool-calling-essence.wav`

解法叫 Tool Calling，工具呼叫。這裡我要先糾正一個常見的誤解：工具呼叫的本質，不是讓模型變強，而是讓模型「不必假裝自己知道」。

我們把查詢、計算、呼叫外部服務這些工作，交給可控的工具去處理；模型只負責決定什麼時候該用哪個工具，以及把工具回傳的結果整理成人話。聽出來了嗎？這正是我們的口訣——數字由工具算、文字由模型寫。工具撈出來的金額、次數、等級是精確的，模型負責把它們串成好讀的回答；如果工具查不到資料，就老實說查無資料，不亂答。

## 03｜呼叫流程怎麼跑

建議檔名：`03-call-flow.wav`

那流程實際上是怎麼跑的？你把工具的名稱、參數跟描述註冊給模型。模型收到問題後，如果判斷需要即時資料，它不會直接回答，而是回傳「我要呼叫某某工具、參數是什麼」；接著 Spring AI 幫你執行那個工具，把結果再送回給模型，模型才根據真實資料組出最終回答。

注意一件事：整個過程中，模型從頭到尾沒有碰你的資料庫。它只是一個「呼叫者」。這個定位，等一下講安全邊界的時候會再回來。

## 04｜@Tool 與 ToolCallback 選型

建議檔名：`04-tool-selection.wav`

Spring AI 裡宣告工具有兩條路，選型原則很簡單：看你有沒有原始碼的修改權限。

第一條路是 @Tool 註解——你自己專案裡的業務方法，直接在方法上標註，最簡單，我們這章主要用它。第二條路是 ToolCallback，適合掛接外部或唯讀的工具：如果是第三方 JAR、你沒辦法加註解，就用 MethodToolCallback 以反射包裝現有方法；如果需要客製化邏輯，就用 FunctionToolCallback，拿 Lambda 加 DTO 封裝。

你不用背這些類別名稱，教學網站上有整理好的選型表；課堂上要記的只有那條判斷：有原始碼就用註解，沒有就用回呼包起來。

## 05｜安全紅線：一律走 Service 層

建議檔名：`05-security-line.wav`

不管走哪一條路，有一條安全紅線不能踩：工具一律透過既有的 Service 層拿資料，絕對不要讓模型直接碰資料庫連線，或繞過你的商業規則。Service 層有交易、有驗證、有權限，AI 只是多了一個呼叫入口，安全責任邊界不能因為接了 AI 就破洞。

這個架構還有一個好處：模型看到的永遠是統一的工具介面，背後是資料庫、內部 Service 還是第三方 API，隨時可以替換擴充，模型的呼叫方式完全不用改。

## 06｜動手：包裝兩個工具類別

建議檔名：`06-hands-on.wav`

我們現在來動手。把講義裡的提示詞複製給 AI Agent——一樣，不用抄，網站上有完整原文。內容是：建立 CustomerTools，用 @Tool 包裝既有的 CustomerService，提供 getCustomers 關鍵字查詢跟 getCustomerDetail 查等級、產業、聯絡方式；再建立 OpportunityTools 包裝 OpportunityService，提供 getOpportunities 查某客戶的所有銷售機會、getDealValue 查金額與成交機率；最後在 ChatController 的呼叫鏈用 .tools() 把兩個工具類別掛上去。

## 07｜description 是寫給模型看的說明書

建議檔名：`07-description-matters.wav`

這裡有個細節特別重要：每個 @Tool 的 description，要用中文清楚描述「什麼情況下該呼叫這個工具」。記住，這段文字不是註解，是寫給大模型看的說明書。它寫得好不好，直接決定模型會不會在對的時機挑對工具。

這也是為什麼我一直說，這門課要你理解的是「為什麼」——你懂了 description 是模型選工具的依據，之後不管換什麼框架、什麼模型，你都知道工具描述該怎麼寫。

## 08｜驗收與下一節

建議檔名：`08-verify-and-next.wav`

做完之後我們來驗證。問它一句：「亞太智能製造目前的風險等級是什麼？有哪些進行中的生意機會？」你會看到兩件事：第一，後端日誌裡出現工具被呼叫的紀錄，證明 AI 真的去查了；第二，回答裡的等級、商機名稱、金額，跟你資料庫裡的一模一樣。再試一個資料庫裡不存在的客戶，AI 會告訴你查無此客戶，而不是編一段故事。

這一刻，你的助理就從聊天玩具，升級成能引用真實客戶資料的企業助手了。下一節我們處理體驗面——用 SSE 把回覆一個字一個字串流到 React 前端，做出打字機效果。我們下一節見。

## 邊念邊操作提示卡

1. 先打開 tool contract，逐一念名稱、輸入、輸出、權限和 description；指出工具只呼叫 Service，不直接碰資料庫。
2. 提問「亞太智能製造目前風險等級和進行中生意機會」，停在 tool trace，等查詢完成後再顯示 AI 回答。
3. 示範查無資料、空查詢和越權，保留拒絕結果；旁白說明模型不能自行補數字。
4. 收尾保存 prompt、trace 和 response，說明下一節會把這個結果串成 SSE。
