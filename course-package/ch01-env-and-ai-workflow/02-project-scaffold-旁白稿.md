# 02-project-scaffold｜建立專案旁白稿

本稿依據 `02-project-scaffold.md` 的教學素材與口語稿整理，供人工錄音使用。共 9 段，錄音時可依段落分開保存，方便後續與投影片時間軸對齊。

建議錄音格式：WAV 或 MP3。每段開頭保持自然，結尾保留約 0.5 秒空白。

## 01｜先能啟動，再談功能

建議檔名：`01-start-before-features.wav`

上一節完成環境建置，這一節，我們要把課程專案建起來。

不過在動手之前，我想先講一個很多初學者會犯的錯：拿到一個新專案的想法，第一件事就是狂寫功能。寫了兩個小時，才發現專案根本跑不起來——可能是依賴衝突、可能是版本不對——然後你就得在一堆自己寫的程式碼裡面，去猜到底是環境問題還是程式問題。這種除錯是最痛苦的，因為變因太多了。

所以這一節的核心原則就一句話：在進入任何功能開發之前，先確認專案可以啟動。

## 02｜用 Spring Initializr 產生骨架

建議檔名：`02-spring-initializr.wav`

那專案怎麼建？我們不手刻。我們用 Spring 官方提供的專案產生器，叫做 Spring Initializr。它會幫你生成標準的 Maven 目錄結構、pom.xml 的依賴設定，還有主程式的進入點。

操作方式有兩種：你可以在 Antigravity(VS Code) 裡打開命令面板，呼叫 Spring Initializr 建一個 Maven 專案，全程不用離開編輯器；也可以直接開瀏覽器到 start.spring.io，設定完下載下來，效果一樣。詳細的操作路徑教學網站上都有，挑一種你順手的就好，這邊我會使用插件來示範。

## 03｜專案設定與版本對齊

建議檔名：`03-project-settings.wav`

接下來你會看到一連串的選項。這裡的重點不是把每個欄位背起來，而是理解幾個關鍵：Spring Boot 版本選 4.0 以上，這是課程範例的基準版本；Java 選 21，記得，要跟上一節裝的 JDK 一致，這是最容易出錯的地方；打包方式選 Jar。專案的 Group 跟 Artifact 照教材填，之後整門課的程式都會長在這個專案目錄下。

## 04｜依賴一次選齊，不砍掉重練

建議檔名：`04-dependencies.wav`

然後是依賴的選擇，這一步很關鍵。本課程需要的依賴，我們現在就一次選定：Spring Web、Spring Data JPA、PostgreSQL Driver、還有 Flyway Migration。

你可能會問：資料庫我們不是第三章才會用到嗎？對，但先選起來。因為這個專案骨架會貫穿整門課——後面的 REST API、資料庫、AI 功能，每一章都在同一個專案上持續疊加。我們不會砍掉重練，所以地基先打好。
另外後續還會講到 Spring Security，由於此套件安裝後功能不容易測試，會等到基礎功能完善後再加上

## 05｜認識目錄結構

建議檔名：`05-directory-structure.wav`

按下產生之後，一個完整的專案就出現在你面前了。我們花一分鐘認識一下這個目錄結構，因為接下來所有的課都在這裡面活動。

有三個位置要特別注意：
第一，src/main/java 底下的套件目錄，是 Java 原始碼的根目錄，你或AI寫的後端程式都放這裡。
第二，resources 底下的 application.properties，是應用程式的設定檔，之後資料庫連線、AI 金鑰都會設定在這。
第三，pom.xml，是 Maven 的依賴跟建置設定。先記住這三個位置的「職責」，之後還能在網頁上對照。

## 06｜首次啟動與預期中的失敗

建議檔名：`06-first-run.wav`

接著就是這一節最重要的動作——首次啟動驗證。打開終端機，進到專案目錄，跑一次 Maven 的編譯。你會看到它開始下載依賴、編譯程式，正常的話最後會出現 BUILD SUCCESS，看到這幾個字才算過關。

這裡先預告一個「預期中的失敗」：如果你直接啟動應用程式，資料庫連線會失敗，因為我們還沒有啟動 Docker、還沒有資料庫。這不是你做錯了，這是預期行為。這一步我們只驗證一件事：Spring Boot 主程式可以被 Maven 執行、類別掃描沒有錯誤。

## 07｜版本控制：存下第一個可回復的基線

建議檔名：`07-git-baseline.wav`

編譯通過之後，還有一個動作很多人會跳過，但我強烈建議你現在就做——版本控制。在專案根目錄執行 git init，把這個目錄變成 Git 儲存庫，然後跑一次 git status --short，看看哪些檔案會被追蹤。

這裡要看清楚一件事：Initializr 產生的專案已經附了一份 .gitignore，所以像 target 這種編譯產物、IDE 的快取檔，都不應該出現在 git 的追蹤清單裡。之後也不要把個人金鑰放進提交。確認畫面上只有預期的專案檔之後，就建立第一個 commit。

為什麼要在這個時間點做？因為現在的專案是一個「剛確認能 BUILD SUCCESS 的乾淨骨架」。把它存成基線，下一節開始讓 AI 動手改東西的時候，不管改壞了什麼，你都有一個隨時可以回復的起點。這是跟 AI 協作最重要的安全網。

## 08｜讓 AI 幫你建骨架

建議檔名：`08-ai-scaffold.wav`

那 AI 在這一節扮演什麼角色？教材裡有一段建骨架的提示詞，你可以請 AI 幫你建立整個課程專案的資料夾結構：一個資料夾放後端程式、一個放之後要做的網頁畫面，並且開始做版本控制。

提示詞的原文網站上都查得到，你要注意的是它的最後一句：「完成後我要能把這個後端空專案實際啟動起來，確認一切就緒。」我們又看到同樣的模式了——先把需求講清楚，讓 AI 產出，最後一定要驗證。如果啟動失敗，把錯誤訊息原封不動貼給 AI，用排錯提示詞讓它幫你修。

## 09｜本節總結與下一節

建議檔名：`09-closing.wav`

總結這一節：用 Spring Initializr 建立標準骨架、一次選好全課的依賴、在寫任何功能之前先讓它 BUILD SUCCESS，最後用 git 存下第一個可回復的基線。

下一節我們暫停動手，來談一個更重要的觀念——AI 協作到底什麼時候該用、什麼時候不該用，把這門課的協作紀律講清楚。我們下一節見。

## 邊念邊操作提示卡

1. 錄製畫面先停在 Initializr 的選項頁，依序指向 Spring Boot、Java 21、Maven、Jar 與四項依賴；每個選項念完再點下一個，讓學員能逐項核對。
2. 下載並開啟專案後，先在檔案樹指出 `pom.xml`、`src/main`、`src/test`，再打開終端機執行 `mvn clean compile`。念到「請等待 BUILD SUCCESS」時停格，讓學員有時間跟做。
3. 示範 `git init` 和 `git status --short` 時，解釋哪些檔案是預期的、哪些檔案不應提交；不要把 status 畫面只當成裝飾。
4. 若啟動時因為資料庫尚未存在而失敗，旁白要說清楚「這不是編譯失敗」，先回到建置證據，再把連線問題留給章節 3。
