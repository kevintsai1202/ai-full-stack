# 04-crm-workbench-design｜CRM 工作台設計思維旁白稿

本稿依據 `04-crm-workbench-design.md` 的教學素材與口語稿整理，供人工錄音使用。共 8 段，錄音時可依段落分開保存，方便後續與投影片時間軸對齊。

建議錄音格式：WAV 或 MP3。每段開頭保持自然，結尾保留約 0.5 秒空白。

## 01｜從業務的一天開始設計

建議檔名：`01-design-from-workflow.wav`

前面三節，工具都到位了：專案跑得起來、JSX 看得懂、視覺樣式也調好了。這一節是本章的重頭戲——我們要把 CRM 工作台真正組裝起來，接上前四章做好的後端。開始寫提示詞之前，先想一個問題：業務人員一天的工作長什麼樣？早上打開系統，先看今天該做什麼；然後查某個客戶的狀況；再追蹤手上的生意進行到哪個階段。頁面設計不是我們想放什麼就放什麼，而是跟著這個工作流走。

## 02｜四個核心畫面

建議檔名：`02-four-core-screens.wav`

照這個思路，工作台有四個核心畫面。第一個是 Dashboard 儀表板，開門見山展示關鍵指標：本月商機總額、待跟進客戶數、即將到期的合約、還有 AI 建議的優先行動——用卡片式佈局，而且每個數字都來自後端 API 的即時聚合，不是寫死的假數字。第二個是客戶列表，能搜尋、能依產業、合約狀態、最後互動時間動態篩選，資料量大時用虛擬滾動，點一列進入客戶詳情。第三個是商機看板，長得像 Trello：每個直欄代表一個商機階段，從 Prospecting、Qualification、Proposal 到 Closing，卡片可以拖拽換欄，換欄就等於更新這筆生意的階段。第四個是 AI 助理，右側浮動面板或獨立頁面，支援 SSE 串流對話跟 Markdown 渲染——這個入口我們這一章先留好位置，功能下一章接 Spring AI 的時候實作。

## 03｜三條元件設計原則

建議檔名：`03-component-principles.wav`

架構上有三條元件設計原則。第一，每個頁面是一個 Route，共用一個 Layout 元件——側欄加頂部導覽，換頁只換中間的內容區。第二，資料請求統一用 Axios，搭配我們第一節設好的 Vite Proxy，所有請求走同一個出口。第三，CSS 用 HSL 色彩系統，方便支援深色淺色主題切換。這三條先立好，AI 產出來的程式碼才會有一致的骨架，而不是每頁各自為政。

## 04｜Axios Interceptor 管登入狀態

建議檔名：`04-axios-interceptor.wav`

接著是本章技術上最關鍵的一塊：登入狀態怎麼管。回想第四章，後端所有 API 都被 JWT 保護著，前端每一次請求都得帶 Token。難道每支查詢函式都手動塞一次 header 嗎？當然不行。答案是 Axios Interceptor，攔截器。它就像 API client 的關卡：請求出去之前，攔截器自動把儲存好的 JWT 附加到 header 上；回應進來時如果後端回 401，代表 Token 過期或無效，攔截器就自動把使用者導回登入頁。「帶 Token」跟「處理過期」這兩件事只寫在一個地方，所有請求自動受惠——這就是你要理解的設計理由，程式碼讓 AI 寫就好。

## 05｜提示詞一：接上後端並記住登入

建議檔名：`05-prompt-auth.wav`

我們現在把這件事交給 AI。教材裡的提示詞用的是很口語的講法：「登入成功後自動記住我的身分，之後每次操作都自動帶著；登入過期就自動導回登入頁重新登入」。提示詞不用抄，教學網站上直接複製。送出後你會看到 AI 做出登入流程、把 Token 存下來，然後建出攔截器。注意，我們沒有講任何 Axios 的技術細節，但因為你懂背後的機制，AI 做出來的東西你看得懂、也驗得動。

## 06｜提示詞二：核心頁面接真實資料

建議檔名：`06-prompt-pages.wav`

再來用下一段提示詞把核心頁面一次做出來：登入頁、放幾張數字卡片的總覽儀表板、可搜尋篩選的客戶清單、分頁切換聯絡人、往來紀錄、生意機會的客戶詳情，還有依階段分欄的商機看板。注意提示詞裡有兩個防禦性要求：沒登入要導回登入頁；載入中、載入失敗、沒有資料三種狀態都要有清楚的畫面——上一節講的骨架屏，這裡就派上用場了。

## 07｜進階：分析圖表與客戶分群

建議檔名：`07-analytics-and-segmentation.wav`

如果你想把儀表板做得更有分析價值，還有兩段進階提示詞。一段是加上經營圖表：商機各階段的漏斗圖、未來幾個月的營收預測、各產業營收分布、客戶風險分布、快到期該續約的客戶、業務績效排行榜，而且要求每張圖點下去能下鑽，看到背後是哪些客戶、哪些生意。另一段是客戶分群：依「多久沒聯絡」、「往來頻率」、「金額大小」三個面向自動評分貼標，分出重點客戶、有潛力、需要喚醒，讓業務一眼知道該先追誰。這兩段都在教學網站上，需要的時候複製就好。

## 08｜驗收、作業與下一章預告

建議檔名：`08-closing-preview-ch6.wav`

最後，也是本章的驗收重點：用測試帳號實際登入一次。你會看到儀表板的數字、客戶清單、詳情頁顯示的通通是後端資料庫裡的真實資料，不是前端寫死的；點圖表能看到明細；登出或 Token 過期會乖乖回到登入頁。能走完這一圈，前後端就是真的接通了。總結一下：這一節我們以業務工作流為軸設計了四大頁面，用 Axios Interceptor 解決 JWT 自動攜帶與 401 導回登入，並驗證了工作台跑的是真實後端資料。接下來的作業，請你把這套前端基本架構完整做出來。而下一章，我們要讓這個工作台真正「智慧」起來——用 Spring AI 的 ChatClient 跟 SSE 串流，把 AI 助理接進來。我們下一章見。

## 邊念邊操作提示卡

1. 先顯示五個工作台入口，依業務一天的工作流從 Dashboard 走到客戶詳情、商機看板和 AI Chat。
2. 示範登入後 Network request 帶 JWT，接著用真實資料載入客戶列表；旁白要指出 response 而不是只念畫面數字。
3. 送出 401 或讓 token 過期，停在登入頁；再展示 loading、error、empty 和圖表下鑽的畫面。
4. 收尾保存測試帳號、Network、角色和下鑽證據，說明下一章從 AI Chat 入口接上 SSE。
