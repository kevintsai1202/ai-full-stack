# 02-testing-strategy｜測試策略旁白稿

本稿依據 `02-testing-strategy.md` 的教學素材與口語稿整理，供人工錄音使用。共 8 段，錄音時可依段落分開保存，方便後續與投影片時間軸對齊。

建議錄音格式：WAV 或 MP3。每段開頭保持自然，結尾保留約 0.5 秒空白。

## 01｜這套系統經得起「驗」嗎

建議檔名：`01-can-it-be-verified.wav`

上一節我們把 AI CRM 串起來、展示腳本也走順了，這一節我們來面對一個更根本的問題：這套系統經得起「驗」嗎？我先丟一個情境給你。假設你寫了一個傳統的測試，斷言 AI 助理回答 APIM 合約狀況時，輸出的字串要完全等於某段預期文字——這個測試今天跑是綠的，明天跑可能就紅了。為什麼？因為 LLM 的輸出天生就有隨機性，同一個問題，它每次的措辭都可能不一樣。

## 02｜答案是分層測試

建議檔名：`02-layered-testing.wav`

所以 AI 功能的測試，不能用傳統「斷言輸出完全相等」的方式，硬套只會做出一堆時好時壞的假測試。那怎麼辦？答案是分層測試——把 AI 功能拆開來，每一層用適合它的方式驗。你等一下會發現一件有趣的事：真正碰到隨機性的，其實只有很小的一部分。

## 03｜前兩層：@Tool 方法與 Prompt 組裝

建議檔名：`03-tool-and-prompt.wav`

我們一層一層看。第一層是 Java 的 @Tool 方法，這一層根本沒有隨機性，就是普通的 Java 程式，用一般的單元測試驗證輸入輸出就好——給它客戶 ID，它回傳的合約資料對不對，斷言下去就是了。第二層是 Prompt 組裝：驗證 system prompt 有沒有正確帶入客戶資料、有沒有設定正確的角色約束。這測的是「我們餵給模型的東西對不對」，同樣是確定性的。

## 04｜後兩層：RAG 檢索與端到端

建議檔名：`04-rag-and-e2e.wav`

第三層是 RAG 檢索：驗證 vector store 查詢有沒有回傳相關文件——問退貨政策，撈回來的該是退貨政策的文件，而不是產品規格書。第四層才是端到端：用 Playwright 模擬真實使用者操作，驗證 SSE 串流有沒有正確顯示在前端。你發現了嗎？四層裡有三層是確定性的測試，真正碰到模型隨機性的只有最後一層，而那一層我們驗的是「流程有沒有走通、格式對不對」，不是逐字比對。這就呼應整門課的信任邊界口訣：數字由程式算、文字由 AI 寫——能用程式驗的，就用程式紮紮實實地驗。

## 05｜三種典型客戶場景

建議檔名：`05-three-scenarios.wav`

那端到端要測哪些場景？我們挑三種典型客戶，剛好對應第三章 seed data 埋好的三種類型。第一種，高價值活躍客戶 APIM：登入後查看客戶詳情、觸發 AI 對話，AI 要能正確引用 RAG 知識庫回答產品問題——這是「資料齊全時答得好」。第二種，資料還很少的客戶：AI 應該誠實回答「查無相關資料」，而不是編造——這是第六章那條信任邊界守則的最終考驗。第三種，流失風險客戶 GlobalMart：AI 摘要要能正確反映互動頻率下降的趨勢。注意，三個場景都要從登入開始走完完整路徑，只測中間一小段是不夠的。

## 06｜上線檢查清單：安全與效能

建議檔名：`06-checklist-security-performance.wav`

測試齊了，最後一關是上線檢查清單。教材裡的提示詞會請 AI 整理清單並逐項幫你檢查，一樣不用抄，網站上查得到。清單有四大面向，先看前兩個。第一是安全性：JWT secret 換成生產金鑰了嗎？開發時圖方便寫死的那把 key 絕對不能上線；CORS 白名單收斂了嗎？API 有 rate limiting 嗎？第二是效能：SSE 連線有沒有 timeout 設定、RAG 查詢的 topK 跟 similarity threshold 合不合理、資料庫連線池大小夠不夠。

## 07｜檢查清單：可觀測性與錯誤處理

建議檔名：`07-checklist-observability-errors.wav`

第三是可觀測性：有沒有結構化日誌？有沒有記錄每次 AI 呼叫的 token 消耗跟延遲？AI 功能是要花錢的，token 花在哪裡你得看得見。第四是錯誤處理：LLM API 掛掉的時候有沒有 fallback？前端能不能優雅地顯示錯誤訊息，而不是白畫面？這四個面向逐項打勾，再配上同一段提示詞幫你準備的一條龍展示腳本，你的結訓驗收就完整了。

## 08｜主軸專案收官

建議檔名：`08-capstone-closing.wav`

走到這裡，主軸專案正式收官。從第一章的一台空機器開始：裝環境、寫 API、資料落地、加上安全防護、蓋出前端工作台、接上 AI 對話、建好 RAG 知識庫，到今天完成整合、測試與上線檢查——你帶走的不是一份聽課筆記，而是一套有登入、有資料、有 AI 助理、有知識庫、有測試、有上線清單的完整企業級作品。把它放進履歷、放上 GitHub。課程還沒完全結束——下一章是我加碼的常用開發技能介紹，包括規格驅動開發的 superpowers、UI/UX 設計智能的 ui-ux-pro-max，還有記憶類技能 deep-memory。恭喜你完成結訓專案，我們下一章見。

## 邊念邊操作提示卡

1. 先顯示三個客戶場景和測試矩陣，逐欄念 API、資料庫、權限、AI、RAG、SSE、瀏覽器與人工驗收。
2. 依 unit、integration、security、AI contract、retrieval、SSE、E2E 順序執行；每層展示命令和輸出。
3. 故意執行一個 401、空資料、provider timeout 或重連案例，停在失敗分類，不要只報紅燈。
4. 結尾展示 release gate，說明綠燈必須來自目前 commit 和可重現環境。
