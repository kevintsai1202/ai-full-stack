# 01-full-demo｜完整 AI CRM 功能示範旁白稿

本稿依據 `01-full-demo.md` 的教學素材與口語稿整理，供人工錄音使用。共 9 段，錄音時可依段落分開保存，方便後續與投影片時間軸對齊。

建議錄音格式：WAV 或 MP3。每段開頭保持自然，結尾保留約 0.5 秒空白。

## 01｜歡迎來到結訓章

建議檔名：`01-welcome-recap.wav`

歡迎來到第八章，也是我們這門課的結訓章。先帶你回頭看一眼走過的路：第一章裝好環境、建立 AI 協作三原則；第二章用 Spring MVC 做出第一批 REST API；第三章讓資料落地到 PostgreSQL；第四章加上 Spring Security 跟 JWT；第五章用 React 19 蓋出 CRM 工作台；第六章接上 Spring AI，讓 AI 助理會串流回話、會查真實資料；第七章用 pgvector 蓋了 RAG 知識庫。七章下來，你手上已經有一套企業級系統的所有零件了。

## 02｜這一章一行新功能都不寫

建議檔名：`02-no-new-features.wav`

那這一章要做什麼？我要很誠實地跟你說：這一章我們一行新功能都不寫。結訓專案的核心目標不是加功能，而是把七個單元的產出真正「串起來」，變成一套你可以放進履歷、可以在面試時當場展示的完整作品。聽起來很簡單對不對？零件都有了，組起來就好。但帶過專案的人都知道，整合往往是最痛的一段。

## 03｜整合的三大挑戰

建議檔名：`03-three-challenges.wav`

整合最常遇到的問題有三類。第一類是環境差異：Docker 容器、JDK 版本、Node.js 版本，在你的機器上跑得好好的，換一台機器就不一致。第二類是跨層整合：前端 Axios 的 base URL 指錯、CORS 設定漏了網域、JWT token 放在 header 的格式不對——任何一環出錯，你看到的都是 401 或 403，而且錯誤訊息長得幾乎一模一樣。第三類是資料流斷裂：seed data 的客戶 ID 跟前端硬編碼的測試 ID 對不起來，系統明明活著，畫面卻永遠「查無資料」。

## 04｜解法：整合檢查清單逐層驗證

建議檔名：`04-layered-checklist.wav`

這三類問題的共通解法只有一個：建立一份整合檢查清單，從資料庫、後端、前端逐層驗證。一層確認沒問題，再往上走一層。千萬不要看到錯誤就前後端到處亂改，那只會把問題越攪越渾。這也是我們整門課一直在講的紀律：先搞清楚問題在哪一層，再動手。

## 05｜把整合交給 AI

建議檔名：`05-ai-integration.wav`

我們現在來實際做整合。教材裡的整合提示詞不用抄，教學網站直接複製就好。它的重點是：請 AI 接續前面所有做好的東西，把後端、網頁畫面、AI 智慧助手、風險與情緒洞察、團隊分析、知識庫問答全部整合起來，確認它們能一起啟動運作。你會看到 AI 逐一檢查每個模組的啟動狀態，發現 CORS 或 token 格式的問題就當場修掉。提示詞後半段還請它針對三種典型客戶建立端到端測試——這三種場景我們留到下一節細講，這一節先聚焦「系統跑得起來、展示得出去」。

## 06｜展示腳本：由下往上證明每一層

建議檔名：`06-demo-script-part1.wav`

系統串起來之後，就是 Demo Day 的重頭戲：展示腳本。展示順序是有講究的，我建議照系統分層由下往上走。第一步，登入系統——證明 Spring Security 加 JWT 正常運作，登入後直接進 Dashboard 看本月指標。第二步，進入客戶列表，用動態篩選找到 APIM 這家高價值客戶，點進去看詳細資訊——證明 JPA 加 Flyway 的資料層是完整的。

## 07｜展示腳本：AI 對話到業務閉環

建議檔名：`07-demo-script-part2.wav`

第三步，開啟 AI 助理，問它「APIM 最近的合約狀況和商機進度」——你會看到回答用 SSE 一個字一個字串流出來，而且裡面的數字是 Tool Calling 從資料庫查來的真數字，不是編的。第四步，再問「GlobalMart 有流失風險嗎？建議怎麼處理？」——同時展示 RAG 知識引用跟對話的歷史記憶。第五步，讓 AI 產生行動建議並確認建立待辦任務，把完整的業務閉環走完，最後開 Swagger UI 秀一下 OpenAPI 文件。這五步，剛好把八章所學各講了一遍故事。

## 08｜實戰忠告與從零驗收

建議檔名：`08-final-verification.wav`

一個實戰忠告：每個步驟的測試資料都要預先準備好，不要在台上現場打字，現場輸入是 Demo 意外的最大來源。腳本走順之後，用教材裡的驗證提示詞做最後把關：請 AI 陪你「從零」完整跑一次——啟動服務、登入、瀏覽客戶、跟 AI 對話並確認數字是真的、看風險與情緒、看儀表板、看團隊分析、再做一次知識庫問答，全程沒有錯誤，就算通過結訓驗收。「從零」這兩個字很關鍵，因為 Demo Day 當天你就是從零開機的。

## 09｜本節總結與下一節

建議檔名：`09-closing.wav`

總結這一節：結訓整合不寫新功能，用整合檢查清單逐層排除環境、跨層、資料流三類問題，再用五步展示腳本把作品講成一個完整的故事。下一節，我們來談怎麼用測試策略跟上線檢查清單，讓這套系統不只展示得漂亮，還經得起驗。我們下一節見。

## 邊念邊操作提示卡

1. 開場先展示環境清單、ready/health 和測試帳號，念到「現在開始完整旅程」才登入。
2. 依序操作 Dashboard、客戶搜尋、詳情、AI 問題、Tool、RAG 引用和建議行動；每一步停在 Network 或畫面留下證據。
3. 重播 401、空資料、工具拒絕、timeout 和 SSE 中斷，明確說明這些不是剪輯錯誤，而是驗收內容。
4. 收尾打開來源追蹤表和 checklist，若任一服務未 ready 就標記 partial，不用 mock 冒充整合。
